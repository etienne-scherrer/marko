## Objective
Add a `marko/clock` package providing a PSR-20 `SystemClock`, a `FakeClock` in `marko/testing`, and adopt the injected clock in the session, token-auth and webhook packages so time-dependent behaviour is deterministically testable.

## Related Issues
Closes #182

## Discovery Notes
- `psr/clock` is not installed; no clock abstraction exists. Packages call `time()` / `new DateTimeImmutable()` directly.
- Adoption sites (no other ticket touches these packages):
  - `marko/session`: `SessionMiddleware` cookie `expires` (`time()`).
  - `marko/session-file`: `FileSessionHandler::gc()` (`time() - $max_lifetime`).
  - `marko/session-database`: `DatabaseSessionHandler::write()` `last_activity` and `gc()`.
  - `marko/authentication-token`: `TokenGuard` expiry check (`new DateTimeImmutable()`).
  - `marko/webhook`: `WebhookDispatcher` signature timestamp, `WebhookVerifier` and `WebhookReceiver` freshness window, `InvalidSignatureException::staleTimestamp()` age, `WebhookDeliveryService` `attemptedAt`.
- The container autowires class-typed constructor params, so a `?DateTimeZone` param on `SystemClock` would make the container try to build a `DateTimeZone`. A union `DateTimeZone|string|null = null` param is not a `ReflectionNamedType`, so the container uses the default.
- The RoadRunner test fixture app (`packages/roadrunner/tests/Fixtures/app/vendor/marko/*`) boots `session-file` with real classes, so it needs a `marko/clock` module stub to bind `ClockInterface`.
- Docs sidebar is autogenerated from `packages/docs-markdown/docs/packages/`; package lists live in root `README.md`, `.claude/architecture.md`, `.claude/project-overview.md`, root `composer.json` (repositories, require, autoload-dev).

## Scope

### In Scope
- `marko/clock` package: `SystemClock implements Psr\Clock\ClockInterface`, `module.php` binding + singleton, tests, README, docs page.
- `Marko\Testing\Fake\FakeClock` (always frozen): `now()`, `setNow()`, `travel()`, `travelTo()`, `assertNowIs()`.
- Inject `ClockInterface` into session, session-file, session-database, authentication-token, webhook; deterministic `FakeClock` expiry tests per package.
- Root monorepo wiring and package lists; `testing.md` FakeClock section.

### Out of Scope
- Adoption in `queue`, `queue-database`, `scheduler`, `ratelimiter`, `cache-redis`, `authentication`, `database` (owned by other in-flight tickets; listed in PR as follow-up).
- `FakeClock::freeze()` — the fake is always frozen, so `freeze()` would only alias `now()` (pseudo-functionality).

## Architecture Notes
- Use `Psr\Clock\ClockInterface` directly (no Marko wrapper interface).
- `marko/testing` requires `psr/clock` only, not `marko/clock`.
- Core must not depend on `marko/clock`.
- Adopting packages require `marko/clock` and take a required `ClockInterface $clock` constructor param (container-built, so source compatible for container users).

## Risks & Mitigations
- Merge conflicts in `packages/testing/` and root `composer.json`/`composer.lock`: keep edits minimal and additive.
- Constructor signature changes break hand-built instances in tests: update every construction site found by grep.
