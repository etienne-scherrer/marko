# Plan: Pest Expectations Registration

## Created
2026-10-05

## Status
ready

## Objective
Make the six `marko/testing` Pest expectations register automatically in every real project by registering them through a Pest plugin instead of a guarded `autoload.files` entry that Composer includes before Pest's `expect()` exists.

## Related Issues
Closes #179

## Discovery Notes
- `packages/testing/src/Pest/Expectations.php` is listed in `autoload.files` and wraps all registrations in `if (function_exists('expect'))`. Composer includes it before `vendor/pestphp/pest/src/Functions.php`, so the guard is false and nothing registers, silently.
- The monorepo only works because `tests/Pest.php` does a plain `require` of the file after Pest has loaded.
- Pest's plugin manager (`pestphp/pest-plugin` `DumpCommand`) writes `vendor/pest-plugins.json` from every installed package's (and the root package's) `extra.pest.plugins`. `Kernel::boot()` calls `CallsBoot::execute()` after its bootstrappers, which boots every `Pest\Contracts\Plugins\Bootable` plugin — in the main process and in each `--parallel` worker (`bin/worker.php` also calls `Kernel::boot`).
- In the monorepo `marko/testing` is installed into `vendor/` as a Composer path dependency, so the monorepo's own `vendor/pest-plugins.json` is generated exactly as in a user project.
- `Pest\Expectation::extend()` is an instance method from `Extendable`; registration must go through `expect()->extend()`. Re-registering overwrites by key, so registration is idempotent.

## Architecture Notes
- One registration list lives in `ExpectationsPlugin::registerExpectations()`; the shim and `boot()` both call it, so parallel tickets adding expectations edit one place.
- `Bootable` is the hook Pest itself uses for this; it is annotated `@internal` in Pest, but it is the documented plugin contract and is how Pest's first-party plugins boot.

## Risks & Mitigations
- Stale `vendor/pest-plugins.json` in an existing checkout: regenerated by any `composer install`/`dump-autoload` (post-autoload-dump hook); noted in the PR.
- Consumer projects that block `pestphp/pest-plugin` in `allow-plugins`: Pest itself needs it, so any working Pest install already allows it.
